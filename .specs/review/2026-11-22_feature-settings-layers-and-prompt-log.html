Author Q&A

Why does usage now stop when two chats are found, instead of taking the busiest?
The busiest chat is often the other one (a long implementation chat next to a short review chat), so the cost of one command was silently booked to another. An error that names both logs, plus the marker that every stage now writes, is always right.
Why is the kit's own settings file a layer, and why are some keys project-only?
A shared kit used as a submodule had its defaults baked into the prompts at generation; reading its file at run time lets a team change a default without regenerating every project. Keys like kit_dir or shells describe the generated kit itself, so a kit's or a developer's value for them would be wrong for the project.
How does "assigned_to null" differ from no assigned_to, if null removes the key?
The merge removes the value but keeps where it was removed ("(removed)" in -Source), so the scripts see "set to nobody in this file" and do not fall back to assigning it to you.
Why are the usage checks committed when testing/ is local?
They use only synthetic logs and specs, and they are the tests of S21 and S22; the rest of testing/ stays a local scratch area (.gitignore keeps only README.md and usage/).

# Stage: UI (on demand)

Keep the screens of a project consistent: one **Looks contract** (colour and font roles), the
**Looks** the app offers (at least dark and light, switchable), the project's **UI conventions**
and a **UI catalog** of its components and pages.

## Commands

```
LOOK: <app> [--looks <name>,<name>] [--logo <path|none>] [--dry-run]
```
Audits the app's styling against the Looks contract and writes a **look spec**
(`.specs/features/<yyyy_mm_dd>_<app>_look_spec.md`). With `--dry-run`, only the findings.

```
UI CATALOG [<folder>]
```
Creates or refreshes `.specs/ui/catalog.md` from the UI source.

## Skills to load

Always: `../skills/ui_designer.md`.

## Files this stage uses

Paths are relative to this file, so they work both inside spec-nx (`stages/ui/`) and in a
generated kit (`.specs/kit/ui/`).

| File | Use |
|------|-----|
| `looks.md` | The Looks contract: colour and font roles, compliance, the neutral Looks |
| `looks/<name>.md` | Company Looks, if a company layer provides them (they replace the neutral ones) |
| `templates/ui_conventions.md` | Shape of `.specs/ui/conventions.md` (project file) |
| `templates/ui_catalog.md` | Shape of `.specs/ui/catalog.md` (generated by `UI CATALOG`) |
| `../spec_template.md` | Shape of the look spec |

Project files: `.specs/ui/conventions.md` (written by people, proposed by this stage),
`.specs/ui/catalog.md` (generated), `.specs/ui/looks.md` (the app's role mapping and the
Looks it supports, kept by the look spec).

## LOOK

1. **Detect the styling** of `<app>` without assuming a framework: the token layer (CSS custom
   properties, theme files, Tailwind configuration), the theming mechanism (`[data-theme]`,
   a class, a theme store, `prefers-color-scheme`), a settings page with a Look switcher, the
   top navigation, and literal colours in components.
2. **Compare with `looks.md`** and the requested Looks (`--looks`, default all available):
   every role defined, every Look shipped, components using roles, switchable at runtime.
   Map the app's variables to the roles.
3. **Findings** (impact ÷ cost): missing role, missing Look, literal colour, font differs, no
   switcher, no theming, top navigation missing or not using roles.
4. **Write the look spec** (or show the findings with `--dry-run`) from `../spec_template.md`:
   - **Part 1:** the detected styling; statements **S1** the app offers at least dark and
     light, switchable from a settings page and remembered; **S2** every colour and font in
     the UI comes from a role; **S3** the top navigation shows the app's own pages and a
     logo (`--logo`: the app's existing logo, else the given path, else the app's name as
     text) and follows the Look; more statements only for other findings.
   - **Part 2:** Steps only for classes with findings — adopt the roles; add each Look; the
     settings page and switcher; the top navigation; replace literal colours; write
     `.specs/ui/looks.md`. Decision rows for the mechanism chosen; a new font is a decision
     (and an ADR if the kit has the documentation stage).
   - Note for the review stage: the change record needs a `tokens` block and `ui` blocks with
     `views` = the Looks.
5. **Report** the spec, the top findings and the next step `IMPLEMENT: <spec>`.

## UI CATALOG

1. **Find the UI source** (components and pages folders of the framework in use).
2. **List components** (name, one-line purpose, inputs / props, path) and **pages** (route,
   purpose, components used, path).
3. **Compare** with the current catalog: new, removed, changed inputs. Check names against
   `.specs/ui/conventions.md` (if it exists; otherwise offer to create it from
   `templates/ui_conventions.md` with what the code already does).
4. **Check design tokens:** literal colours, spacing and font sizes in components.
5. **Write `.specs/ui/catalog.md`** from `templates/ui_catalog.md` with today's date, and
   report: components, pages, new, removed, token findings.

## Never

- Change UI source code — this stage writes specs and `.specs/ui/` only.
- Invent colours: values come from the Looks; a missing value is a finding.
- Copy brand assets (logos, brand colours) into spec-nx or the kit — they come from the
  project or the company layer.
- Edit `.specs/ui/conventions.md` without the user's consent.
